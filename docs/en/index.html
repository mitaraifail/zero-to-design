From a fuzzy idea
to a living design system.

zero-to-design is an interactive agent skill: through guided conversation, it helps you define the product, gather references, choose directions, iterate interfaces, and ultimately produce an evolving DESIGN.md, real page designs, and motion constraints. Built for teams without a designer.

npx skills add mitaraifail/zero-to-design

Seven Phases, One Closed Loop

Each phase has a clear deliverable; the next step only begins after user approval. DESIGN.md exists as a draft from Phase 4, evolves with feedback, and is finalized in Phase 7 — rather than being generated out of nowhere at the end.

A Real Run · Pulse

All artifacts below come from one complete real run: building a design system from scratch for Pulse, an indie-developer dashboard. Every artifact is a real file you can open and interact with — not screenshots.

Phase 1 · Product Definition: Asking the fuzzy idea the right questions

The user only said “I want to design a dashboard for indie developers,” and the skill narrowed it down to a clear product definition through 8 key questions. Below is a real excerpt from that run:

Q · What is the product name?Pulse
Q · What does it do in one sentence?Rolls revenue, user, and event data into one clear homepage so you know if anything is off in 30 seconds each morning.
Q · Who is the typical user?Full-stack / backend engineers, indie developers, and one-person-company founders.
Q · What is the user’s mindset when opening the page?“Is my product okay today?” — confirm in 30 seconds, rule out bad news, maybe spot a small win.
Q · What is the core differentiator vs. Stripe / GA / self-built dashboards?It proactively tells you today’s status every morning instead of waiting for you to dig.
Q · What atmosphere should the interface convey?Calm + Speed
Q · What is the target platform?Web
Q · Any existing brand assets?None

Answered questions are not repeated; missing answers are inferred by the agent and labeled “agent inferred.” Produces 01-product.md.

Phase 2 · Reference Gathering: Planting aesthetic seeds

The agent dynamically recommends four categories of references based on the product definition, asking the user to browse each and share overall impressions and local annotations:

  • Similar products (clear but not cold dashboards): Stripe Dashboard / Linear / Plausible Analytics / Fathom Analytics
  • Cross-category mood (how Calm + Speed is expressed): Notion / Kinfolk / Aesop / Monocle
  • Design inspiration galleries (layout and interaction details): Mobbin / Awwwards / Godly
  • Typography inspiration (font pairings): Typewolf / Fontshare

This user gave explicit preferences early. These raw notes are recorded verbatim and become hard constraints for Phase 3:

Light mode, no default dark mode. No purple, no blue as primary, no gradients. Continue.

Phase 3 · Direction Selection: Constraints first, directions second

First, the skill scans installed design skills and asks the user to pick the main constraint — because everyone’s preferred design skill is different. The scan and selection for this run:

✅ Available: frontend-design (main constraint), impeccable (full package),
   animate / audit / clarify / critique / layout / polish / typeset (enhancements)
❌ Discovered but not installed: bolder, shape, colorize, arrange, delight

A. frontend-design + available enhancement skills (recommended)
B. frontend-design only
C. Built-in rules only
D. Custom combination

User reply: “Use impeccable as the main constraint.”

Phase 7 · DESIGN.md Finalized

The draft is finalized into the final design system: a multi-chapter structure covering design soul, tokens, component specs, UX constraints, red lines, and agent usage guidelines. It becomes the single source of visual truth for all subsequent development — AGENTS.md references it, and any new session’s agent must read it before starting. Here are the first two chapters from the real file:

## 1. Design Soul

Pulse is a data dashboard for indie developers. Its visual style is “editorial calm”:
like a well-typeset morning newspaper, it builds order through hairline rules,
whitespace, and information density rather than stacked cards and ornamentation.
It aims to ease the low-level anxiety of “how is my product doing today?” within
30 seconds.

Color strategy: warm light gray background + deep charcoal text + forest green accent.
Green represents “normal/healthy” and only appears in statuses and positive changes;
warnings and errors use low-saturation warm brown / sienna red that is not harsh on the eyes.

Typography strategy: Display uses Source Serif 4 to bring a human editorial quality;
Body uses Manrope to ensure data readability; Mono uses JetBrains Mono for amounts,
percentages, and timestamps. The numbers themselves are the protagonists; no charts required.

## 2. Tokens (excerpt)

| Name            | Token              | Role                                          |
|-----------------|--------------------|-----------------------------------------------|
| Page Background | --bg-page          | Page background, creates a warm paper feel    |
| Primary Text    | --text-primary     | Headings, large numbers, body emphasis        |
| Accent          | --accent           | Brand identity, positive status, primary action |
| Card Surface    | --surface-card     | Cards, navigation, action item backgrounds    |
| Subtle Border   | --border-subtle    | Hairline rules, card borders, dividers        |

Role usage rules: --accent is for accents only; do not use it for large fills...
